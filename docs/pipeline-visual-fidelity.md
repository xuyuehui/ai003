# 画面精细度提升流水线

> 这份文档回答一个问题：**从现在这张"能看但粗糙"的图，按什么顺序、做什么，才能到电影级？**
> 结论先说：**从上往下修 —— 剪影 → 光影 → 材质 → 细节 → 后期**。反过来做，大部分时间会白花。

## 0. 现在的位置（L0）

已具备：2 m 顶点地形 + 顶点色、程序化双日天空、两盏方向光、全屏高度雾、沙纹/细节法线、
ACES + Bloom + 分离色调 + 颗粒 + 暗角、程序化井塔/广场/帆撬/人形、服务器下发的沙暴墙。

**判断**：构图和色调对了，但它是"离线渲染的游戏截图"，不是"电影画面"。差距集中在三处：
轮廓太软、材质太均一、近景没有资产细节。

## 1. 一条铁律

> **人眼对"轮廓"和"光影"的敏感度，远高于对贴图分辨率的敏感度。**

把 4K 沙纹贴图贴在一个轮廓像馒头的沙丘上，还是馒头；把 1K 贴图贴在有锐利脊线和正确阴影的沙丘上，
已经像电影。所以顺序不能乱。

## 2. 分级路线（L1 → L6）

| 级别 | 目标 | 具体动作 | 工期 | 验收（怎么算变好） |
| --- | --- | --- | --- | --- |
| **L1 剪影** | 沙丘像沙丘、岩脊像刀 | 高度场 2 m → 1 m（局部 0.5 m）；脊线锐化（侵蚀/脊状噪声）；岩石用柱状节理高度 | 1–2 天 | 200 m 外的沙脊在屏幕上仍有 3–5 个可辨识起伏；轮廓没有"融化"的切线 |
| **L2 光影** | 体积感 | 主光角度按光段分级；第二盏光参与投影；加强 SSAO/接触阴影；高度雾分 2–3 层；补体积光柱 | 2–3 天 | 阴影区有层次不是死黑；远景至少 3 层明度；逆光有明确的亮边 |
| **L3 材质** | 沙/盐/岩三种东西 | 分层材质（坡向 + 高度 + 曲率混合）；沙：三尺度法线 + 各向异性高光 + 包裹漫反射；盐：视差 + 裂纹 + 强镜面；岩：三平面 + AO + 边缘磨损 | 3–5 天 | 近景 5 m 内能数出三档尺度细节；同一材质在正午/黄昏不糊成一片 |
| **L4 资产** | 近景不空 | 井塔/广场/帆撬换成带倒角、接缝、磨损的模块化模型；角色换层叠布料 + 陶瓷片；散布岩石/残骸/脚印/车辙 | 1–2 周 | 近景 20 m 内有 3 种以上材质与尺度对比 |
| **L5 后期** | 电影感 | LUT 分级；长焦 + 轻景深；运动模糊；镜头光晕；Bloom 分层；2.39 遮幅 | 2–3 天 | 与概念帧并排，色相/对比差异 ±10% 内 |
| **L6 环境叙事** | 世界有人住过 | 风蚀痕、车辙、营地痕迹、远景色块 | 3–5 天 | 不看 HUD 也能说出"这里发生过什么" |

## 3. 现在最该做的三件事（按 ROI 排序）

1. **L1 地形几何**：把高度场从 2 m 提到 1 m（近处 0.5 m），加脊线锐化。
   现在"粗糙感"的主因不是贴图，是**轮廓太软**。
2. **L3 材质分层（第一步）**：不要再只用一张顶点色。按坡度/高度/曲率混合三层材质，
   沙丘的迎风面、背风面、丘间地应该是三种不同的沙。
3. **L4 近景资产（第一步）**：井塔和广场是一块块"光板"，加倒角、接缝、磨损就能立刻不一样。

## 4. 每一步怎么验收

统一用 `AI003/Render Ashkar Still` 的四个固定机位出图，并排对比，同时看三个数：

| 指标 | 目标 |
| --- | --- |
| 近景 texel density | ≥ 512 px/m（5 m 内） |
| 阴影分辨率 | ≤ 5 cm/texel（100 m 内） |
| 雾/大气层数 | ≥ 3 层 |
| 帧率 | ≥ 60 fps（1080p） |

另外复用 [03-art-direction.md](worldview/03-art-direction.md) §10 的截图评审清单。

## 5. 不要做的事

- **不要先调后期**：LUT、景深、颗粒会把问题糊住，评审时看不出真实差距。
- **不要先堆粒子**：沙尘、火花、光晕是最后 10% 的加分项，不是前 90%。
- **不要全场景高模**：先解决 1% 的镜头画面，再谈全局。

## 6. 工具链（每一步都走同一条流水线）

```
高度/掩码生成  →  场景烘焙  →  材质  →  出图  →  回归
worldgen          AI003/Bake      shader/    AI003/Render    PlayMode
或 Unity 侧导入    Static Scene    ShaderGraph Ashkar Still    测试 + 截图对比
```

| 步骤 | 命令/入口 | 产物 |
| --- | --- | --- |
| 世界数据 | `scripts\generate-world.cmd`（或 Unity 自己的高度导入） | `world/` |
| 静态场景 | 菜单 `AI003/Bake Static Scene` | `Assets/Scenes/AshkarStatic.unity` + `Assets/Generated/` |
| 出图 | 菜单 `AI003/Render Ashkar Still` / `AI003/Render Play Frame` | `artifacts/ashkar/*.png` |
| 回归 | `scripts\test-unity-playmode.cmd` | PlayMode 结果 |

> `Assets/Generated/` 是烘焙产物（地形网格、材质、天空材质），已在 `.gitignore` 里；
> 新机器打开静态场景后跑一次 `AI003/Bake Static Scene` 即可，缺失时 `WorldBootstrap` 会自动回退到运行时构建。

## 7. 范围变化（本次调整）

- **Unity 不再与 UE 共享世界数据**：`world/` 现在只是 Unity 自己的高度场来源，UE 保持旧数据、不再对齐。
- **服务器仍然共享**：只需要共享网络与世界事件（`join/move/snapshot`、`world.tide/elder/nodes`），
  两端各自渲染，互不影响。
- **场景静态化**：地形、地标、灯光、天空、后期都烘焙进 `AshkarStatic.unity`；
  Play 时只生成玩家与相机，不再"一按 Play 长出一整个世界"。
